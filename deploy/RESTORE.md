# CodeAtlas Restore Runbook

The backup intentionally excludes Git worktrees and logs. Restore MySQL, Chroma,
original document bytes, the provider-credential encryption key, blog Markdown,
environment configuration, and the repository manifest.

1. Verify the archive before extracting:

   ```bash
   sha256sum -c codeatlas-YYYYMMDD-HHMMSS.tar.gz.sha256
   ```

2. Stop the API and extract to a new staging directory:

   ```bash
   systemctl stop codeatlas
   install -d -m 0750 /var/lib/codeatlas-restore
   tar -C /var/lib/codeatlas-restore -xzf codeatlas-YYYYMMDD-HHMMSS.tar.gz
   ```

3. Verify the target MySQL database exists and `/etc/codeatlas/codeatlas.env`
   contains its SQLAlchemy URL. Generate a temporary MySQL client option file,
   then import `codeatlas.sql`. Keep that option file mode `0600` and delete it
   immediately after the import. Restore both `chroma` and `documents` into
   `/var/lib/codeatlas`. Restore `provider-credentials.key` as
   `/var/lib/codeatlas/.llm-config.key` with owner `codeatlas:codeatlas` and mode
   `0600`; without the original key, encrypted LLM and Embedding credentials are
   unrecoverable. Then
   set ownership to `codeatlas:codeatlas` and mode `0750` on directories.

   The client option file must contain the decoded credentials from
   `CODEATLAS_DATABASE_URL`:

   ```ini
   [client]
   user=codeatlas
   password=RESTORED_DATABASE_PASSWORD
   host=127.0.0.1
   port=3306
   protocol=tcp
   ```

   Import the dump with:

   ```bash
   chmod 0600 /root/codeatlas-mysql-client.cnf
   mysql --defaults-extra-file=/root/codeatlas-mysql-client.cnf codeatlas \
     < /var/lib/codeatlas-restore/codeatlas.sql
   rm -f /root/codeatlas-mysql-client.cnf
   ```

4. Review `codeatlas.env` before replacing `/etc/codeatlas/codeatlas.env`. Restore
   blog Markdown to `/opt/codeatlas/blog/src/content` only when source content is
   maintained on the server.

5. Start CodeAtlas and verify both probes:

   ```bash
   systemctl start codeatlas
   curl --fail http://127.0.0.1:8010/api/v1/health
   curl --fail http://127.0.0.1:8010/api/v1/ready
   ```

6. Git worktrees are regenerated by queuing a sync for every repository in
   `repositories.json`. Do not restore journald or Nginx logs.
